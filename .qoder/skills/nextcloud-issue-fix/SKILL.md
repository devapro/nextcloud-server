# Nextcloud issue → fix → PR (via fork)

End-to-end pipeline with five phases and one sub-agent per phase. The orchestrator (you,
main agent) owns the human approval gates; sub-agents never talk to GitHub write APIs.

```
find ─▶ TRIAGE ─▶ [human picks] ─▶ REPRO (fails on clean tree) ─▶ FIX ─▶ VERIFY (Docker+Chrome) ─▶ [human OK] ─▶ SHIP (push+PR to fork)
```

## Non-negotiables

1. **Gates.** Three human confirmations, each asked fresh in the conversation:
   (a) chosen issue from the shortlist; (b) `git push` of the finished branch; (c) `gh pr create`.
   One approval = one action, never standing consent.
2. **Write scope.** Pushes/PRs go only to `origin` = `devapro/nextcloud-server` (base `develop`).
   Upstream `nextcloud/server` is read-only: no issue comments, no labels, no upstream PRs.
   Suspected vulnerabilities abort the pipeline → HackerOne via the human (AI policy).
3. **Repro before fix.** No code changes until a failing test demonstrates the issue on a
   clean tree. No PR offer until the verification matrix in `references/verification.md` is complete.
4. **Generated artifacts** (dist/, autoload classmaps, openapi*.json, psalm baselines) must be
   regenerated by their tooling and included in the same commit — never hand-edited.
   Details in `references/policy-pr.md`.
5. **Foreign work in the tree.** The checkout may hold the user's unrelated uncommitted changes
   (currently: `AGENTS.md`, `REUSE.toml`, `build/files-checker.php` — see envcheck output).
   Never revert, stash or stage them; create the fix branch from `origin/develop` in a
   dedicated `git worktree` (`.qoder/issue-fix/<n>/worktree`) when the main tree is dirty,
   and stage only your own files.
6. **`.qoder/` is local-only**, never committed; `build/files-checker.php` flagging it as an
   extra root entry is expected noise.

## Setup

Read `AGENTS.md` first if not in context. Then run
`bash .qoder/skills/nextcloud-issue-fix/scripts/envcheck.sh` and bootstrap whatever it flags
(`composer install`, `npm ci`, `git submodule update --init --depth 1`, `npx playwright install chromium`).
Long installs: run in background, continue only after all OK. Create `.qoder/issue-fix/<n>/`
per issue; it holds `issue.json`, `triage.md`, `repro.md`, `verification.md`, `evidence/`,
`pr-body.md`, `worktree/`.

## Sub-agent dispatch

Agents are defined in `.qoder/agents/nc-*.md`. For each phase call
`Agent(subagent_type: "nc-issue-triage" | …)`; if the harness rejects the type
("Unknown agent type"), fall back: read the agent's `.md` and dispatch `general-purpose` with
the file body pasted verbatim as the first block of the brief, followed by `## Task` (issue
number, workspace path, phase inputs) and `## Report` (write files to workspace, return a
≤300-word summary). Always pass absolute paths.

| Phase | Agent | May touch |
|---|---|---|
| 1 TRIAGE | `nc-issue-triage` | read-only GitHub + repo |
| 2 REPRO | `nc-issue-repro` | untracked spec + Docker, no code edits |
| 3 FIX | `nc-fix-implement` | code edits + local tests, no git mutations |
| 4 VERIFY | `nc-verify-browser` | Docker/browser, evidence files |
| 5 SHIP | `nc-pr-ship` | git branch/commit local; push/PR only with gate token |

## Phase 1 — TRIAGE

`--find`: dispatch `nc-issue-triage` with instruction to apply
`references/triage.md` (queries, hard exclusions, 0-10 scoring) and write the ranked
shortlist to `.qoder/issue-fix/triage.md`. Present top 5 to the human — **gate (a)**.
`good first issue` / enhancement candidates may surface but must be labeled as such;
the human opts in explicitly. A given `issue-number` skips search: still run triage
scoped to that one issue (exclusions + "still present" check) before repro.

## Phase 2 — REPRO

Dispatch `nc-issue-repro`: fetch issue body, boot the Docker Playwright harness
(`references/verification.md`), write a **failing** test (Playwright spec preferred;
PHPUnit/occ only when not UI-reachable), prove it fails with the issue's symptom on clean
code, and write `repro.md` (root-cause hypothesis + implicated files). Flaky or
unreproducible after honest effort → report back; go to human with options (retry different
issue / proceed on code-inspection only, explicitly degrading what "verified" will mean).

## Phase 3 — FIX

Dispatch `nc-fix-implement`: minimal fix for the root cause per `repro.md`, respecting
`AGENTS.md` conventions (strict_types, SPDX headers, OCP-API `@since` rules, tabs, `…`).
Regenerate whatever the edits require (`npm run build` / `autoloaderchecker.sh` /
`openapi-checker.sh` / psalm baseline). The repro spec must now pass; run the matching unit
tests and gate checkers. No commits, no branch — working tree only.

## Phase 4 — VERIFY

Dispatch `nc-verify-browser`: full matrix in the Docker instance — repro spec green, whole
adjacent `tests/playwright/e2e/<area>/` suite green, PHP checks re-run on the final tree;
then the interactive browser-use walkthrough of the issue's exact steps with before/after
screenshots into `evidence/`. Fill `verification.md` matrix; any unverified cell must be
stated, not glossed.

## Phase 5 — SHIP

Summarize to the human: branch name, files changed incl. regenerated artifacts, matrix,
evidence. **Gate (b)** — on approval, dispatch `nc-pr-ship` with token
`USER_APPROVED_PUSH=<branch>`. It creates the branch/worktree commit (Conventional Commits,
`Fixes #<n>`, `Assisted-by:` trailer — ask the human for the model string first, never guess;
never `Signed-off-by`) and pushes to origin. Then show the exact PR title + body from
`references/policy-pr.md` template. **Gate (c)** — on approval, re-dispatch with
`USER_APPROVED_PR=yes` to run `gh pr create --repo devapro/nextcloud-server --base develop`.
Report the PR URL.

## Resume / abort

`continue <n>`: read `.qoder/issue-fix/<n>/` to find the last completed phase and resume the
next one. On abort (human says stop, or policy conflict): leave the workspace and branch
local, report state; never `git reset --hard`, never delete the user's work.
