# Agent notes

Clone with `git clone --recurse-submodules`. `3rdparty/` is a submodule; PHP will not boot without it. Do not vendor PHP libraries into this tree — bump them in [nextcloud/3rdparty](https://github.com/nextcloud/3rdparty) first, then point the submodule at that SHA (see `3rdparty/README.md` when doing a dependency bump). PRs that touch `3rdparty` or `version.php` are rejected unless the submodule matches HEAD of `master` / `stableXX` on that repo; maintainers can comment `/update-3rdparty` (not available on forks).

PHP 8.3–8.5 (`versioncheck.php` dies on `<8.3` and `≥8.6`). Composer `platform` is 8.3 even though CI also runs 8.5. `composer i` installs into `lib/composer/` (not `vendor/`) and `vendor-bin/*`. Required extensions are those in `composer.json` (`ext-apcu` included) — set `apc.enable_cli=1` or CLI/`occ` will not see APCu. Post-install dumps the autoloader `--no-dev`; a plain `composer dump-autoload` leaks bamarni/bin-plugin into the committed classmap and fails `build/autoloaderchecker.sh`. After adding/renaming shipped PHP classes run `bash build/autoloaderchecker.sh` and commit the result (it resets `apps/*/composer/composer/installed.php` — leave that file alone). Each shipped app’s Composer project lives in `apps/<id>/composer/`. Call phpunit/psalm/cs-fixer via `composer run …` (`lib/composer/bin` is not on a bare PATH).

Node `^24` / npm `^11.3` from the **repo root** (`npm ci`). There are two frontends because npm workspaces break with two Vue majors — do not add workspaces. Root scripts fan out via `build/demi.sh`. Vue 3 + Vite: `build/frontend` (most apps). Vue 2 + webpack: `build/frontend-legacy` (`core`, `files`, `files_sharing`, `settings`, `updatenotification`, `workflowengine`). App dirs there are **symlinks** to `apps/<id>` or `core`; a new bundle needs the symlink **and** an entry in `build/frontend/vite.config.ts` or `build/frontend-legacy/webpack.modules.cjs`. To watch one legacy app: `MODULE=<id> npm run watch`. `dist/` is committed (gitattributes: binary); CI rebuilds and fails on a dirty tree. Rebuild with `npm run build` (also compiles SCSS/icons). Maintainers may comment `/compile`, `/compile fixup`, `/compile amend`, or `/compile rebase` (not on forks). `make clean` deletes `dist/` — do not leave it unbuilt.

`config/config.php` and `config/*.config.php` are gitignored. Extra `*.config.php` files merge on top of `config.php` (natsort); writing config **strips comments** from `config.php`, so put comments/constants in `*.config.php`. `NC_<KEY>` env vars override config keys. Do not commit `config/` runtime files or `data/`. Do not hand-edit `.htaccess` — `occ` injects a `DO NOT CHANGE ANYTHING` block and `build/htaccess-checker.php` fails. `occ` as root drops to the `config.php` owner. First-time install: `mkdir -p data && php occ maintenance:install --database=sqlite --admin-user admin --admin-pass admin` (needs `config/CAN_INSTALL`). Then `composer run serve` → `http://localhost:8080/index.php` (PHP’s built-in server has no `.htaccess` rewrites). Serve runs `occ config:system:set overwrite.cli.url` first, so it fails unless the instance is already installed. Env: `NEXTCLOUD_HOST` (default `localhost`), `NEXTCLOUD_PORT` (`8080`), `NEXTCLOUD_WORKERS` (`4`, sets `PHP_CLI_SERVER_WORKERS`). Optional Nix: `direnv` + `flake.nix` (backport flake changes to `stable30+`). DevContainer (`.devcontainer/`): Apache `:80`, Postgres, `admin`/`admin`; image is PHP 8.4 + nvm Node 22 (README still says Node 16; `package.json` engines are Node 24).

PHPUnit needs an installed instance. Minimal: the sqlite `occ maintenance:install` above, then `composer run test` (`tests/phpunit-autotest.xml`, includes DB groups). Match CI no-DB: Redis on `localhost:6379` + `phpredis`, `mkdir data`, `cp tests/redis.config.php config/`, `cp tests/preseed-config.php config/config.php` (sets `tempdirectory` to `/dev/shm` — Linux only), `./occ maintenance:install --database=sqlite --database-name=nextcloud --database-user=root --database-pass=rootpassword --admin-user admin --admin-pass admin`, `php -f tests/enable_all.php`, then `composer run test -- --exclude-group DB --exclude-group SLOWDB --exclude-group Memcached --exclude-group PRIMARY-swift --exclude-group PRIMARY-s3 --exclude-group PRIMARY-azure`. DB-only: `#[Group('DB')]` (or `#[Group(name: 'DB')]`) plus `composer run test:db` (CI sqlite also starts Redis and wants ghostscript/ImageMagick HEIC for preview tests). `apps/files_external` is not in that xml — `composer run test:files_external`. Multi-DB / docker DBs: `./autotest.sh sqlite [tests/...]` (phpunit ≥ 11.5, writable `config/`, **overwrites** `config.php` with a backup; `ENABLE_REDIS=true` copies redis config; `USEDOCKER=1` when local mysql/pgsql binaries are wrong). `TEST_DONT_LOAD_APPS=1` skips loading every `apps/*`. Frontend unit: `npm test` after `npm ci` (Vitest over both frontend trees).

OpenAPI: apps without a `.noopenapi` file must have generated specs; `composer run openapi` / `bash build/openapi-checker.sh` and commit JSON. Keep `ResponseDefinitions.php` in the same app in sync (Psalm types feed the spec). New **root** entries need `build/files-checker.php` or CI fails the tarball allowlist. New shipped apps also need the `.gitignore` exception and a `psalm.xml` directory entry (`build/psalm-checker.sh`). Psalm CI runs `--update-baseline` then `git diff --exit-code` — fix issues or deliberately commit baseline edits; `lib/composer` diffs are ignored. `composer run rector:strict` must be a no-op on its path allowlist (`build/rector-strict.php`). `composer run cs:fix` / `cs:check` for PHP.

`OCP\` (`lib/public`): PHPDoc with `@since` on classes and public/protected methods/constants; do not typo `@depreacted`. A few newer OCP files require `OCP\AppFramework\Attribute\*` instead (`build/psalm/OcpSinceChecker.php`). `NCU\` (`lib/unstable`): `@experimental` on classes and non-private members — not a stable API. Current product version is in `version.php` (use it for new OCP `@since`). Fourth `OC_Version` digit is an internal DB-upgrade counter, not a public patch.

Do not edit `*/l10n/*.json` or `*/l10n/*.js` — translations go through Transifex. In `t()`/`n()` strings use an ellipsis `…`, not `...` (`build/triple-dot-checker.php`). New files: SPDX headers per `contribute/HowToApplyALicense.md` (read it when adding a file). Existing generic “Nextcloud GmbH and Nextcloud contributors” headers: add your name to `AUTHORS` (not `AUTHORS.md`). REUSE CI is required.

Commits: Conventional Commits `type(scope):` (scope is usually the app id), human `Signed-off-by` via `git commit -s` (real name; see `.github/CONTRIBUTING.md` when opening a PR). Coding-agent identities in `Signed-off-by` fail CI. If AI was used, add `Assisted-by: AGENT_NAME:MODEL_VERSION` on each affected commit and tick the PR AI checkbox; write PR/review text yourself. No `fixup!`/`squash!` on non-draft PRs. Changed PHP/JS needs tests; new features must be exercised on a live instance by the author. Security issues: HackerOne, not GitHub. Ready-for-review PRs targeting `master`/`stable*` are blocked while `OC_VersionString` contains `RC`, and while the target `stableXX` is past EOL. Playwright e2e CI on `master` runs only with labels `3. to review`, `4. to release`, or `force-e2e-tests`, or if `tests/playwright` is touched.

Playwright needs a Docker daemon and pulls `ghcr.io/nextcloud/continuous-integration-shallow-server` (`BRANCH` defaults to `master`; `DOCKER_SOCKET` defaults to `/var/run/docker.sock`). Once: `npm run playwright:install`. Default: `npm run playwright` (projects `default` + `admin-settings`) on `http://localhost:8042/index.php/`. Install-wizard tests: `PLAYWRIGHT_SETUP=true npm run playwright:setup` only — they wipe the shared server; never combine with other projects. CI setup job also starts mysql/mariadb/postgres/oracle. `admin-settings` is serial. Import `test`/`expect` from `tests/playwright/support/fixtures/`; do not construct page objects in specs. Locator methods stay sync; `waitForResponse` **before** the click. Details and POM conventions: `tests/playwright/README.md` when adding e2e.

## Build / run / test

Build JS: `npm ci && npm run build` (Node `^24`, npm `^11.3`; root `postinstall` already installs both frontend trees). `npm run dev` is unminified; `npm run watch` watches both. `make` is JS-only and `rm -rf dist` first. PHP: `composer i`.

Run: `mkdir -p data && php occ maintenance:install --database=sqlite --admin-user admin --admin-pass admin && composer run serve` → `http://localhost:8080/index.php`.

Test PHP: `composer run test`. Test JS: `npm test`. E2E: `npm run playwright:install && npm run playwright`.
